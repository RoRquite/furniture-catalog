## 1. Stack

- **Vanilla ES-модули + CSS**, без фреймворков и `npm install`
  (Node 24 нужен только для build/тестов).
- Тесты: встроенный `node:test` (15 проверок ядра).
- Dev-сервер: собственный `scripts/dev-server.mjs` (~30 строк).
- Выбор обоснован: Mini App — это одна страница с локальными данными;
  тяжёлый tooling не даёт пользы на этом этапе.

## 2. Структура проекта

См. README.md. Данные (`data/*.json`), изображения (`public/images/*.svg`,
генерируются скриптом, без внешних URL), логика (`frontend/js/core/*` —
чистые тестируемые модули), рендер (`frontend/js/ui/render.js`),
build-гейт с валидацией контрактов данных.

## 3. Экраны

1. **Каталог**: название + карточки 3 категорий.
2. **Категория**: ← Назад + список товаров категории.
3. **Карточка товара**: изображение, название, описание, цена,
   характеристики + кнопки ← Назад / Следующий → / ♡ В избранное / Заказать.
4. **Избранное**: список + переход в товар + возврат в каталог;
   пустое состояние с подсказкой.
5. **Не найдено**: явная обработка отсутствующего товара/категории.

## 4. Кнопки и navigation flow

Настоящий стек истории в `core/router.js`: каждый `navigate` push'ит текущий
экран, `back()` pop'ит ровно предыдущий — fake navigation исключена.

- `← Назад`: предыдущий логический экран; в Telegram дублируется системной
  BackButton (`telegram.showBackButton`), вне Telegram — кнопка в UI.
- `Следующий →`: следующий товар категории; **после последнего — первый**
  (выбран wrap-around, поведение единообразное).
- Из карточки → назад в категорию; из любой глубины → «Перейти в каталог»
  (`router.reset()`).

## 5. Избранное

Клиентское localStorage (`fc_favorites_v1`): добавить / убрать (toggle) /
открыть список / перейти в карточку товара / пустое состояние. БД сознательно
не подключена.

## 6. Order

`buildOrderText()`: «Хочу заказать: <Название> | ID | Цена».
Контакт конфигурируется в `data/config.json → order.contactUrl`.
Пока стоит placeholder — кнопка НЕ открывает чат по фиктивной ссылке, а
показывает текст заказа пользователю (никаких неработающих действий).
После замены контакта текст копируется в буфер и открывается чат через
`telegram.openTelegramLink` / `window.open`.

## 7. Telegram integration

`core/telegram.js`: определение запуска внутри Telegram (`tg.ready/expand`),
theme parameters (+`themeChanged`), viewport через expand, системная
BackButton, openTelegramLink для заказов. В обычном браузере — dev-fallback,
приложение полностью работоспособно.

## 8. Тесты — 15/15 PASS (`npm test`)

Покрыты все 14 требуемых кейсов + контракт данных:
открытие каталога/категории/товара, Back, Next, last→first wrap,
добавление/удаление избранного, экран избранного, переход в товар, Order
(текст содержит имя+ID, placeholder-контакт не открывается), возврат в
каталог, отсутствующий товар, пустое избранное, demo/currency контракт.

## 9. Manual E2E — PASS (logic-level walkthrough)

Полный сценарий задания выполнен шаг за шагом через те же модули, к которым
привязаны кнопки UI:

```
Каталог → tables → furniture-001 → Следующий(furniture-002)
→ Следующий(furniture-003) → Назад(product:furniture-002)
→ В избранное(["furniture-002"]) → Избранное(1 шт)
→ Товар furniture-002 → Заказать(«Хочу заказать… ID: furniture-002») ✓
```

Кликовая проверка в реальном браузере/Telegram требует GUI — см. §11.
